# Knot 设计边界

## 目标

提供可阅读、可运行、可裁剪的 Kotlin 全栈参考工程。让使用者理解如何构建多端社交应用，保留替换数据库、上传、登录和推送服务的能力。

## 职责划分

| 能力 | Knot 可沉淀内容 | CS26 负责内容 |
| --- | --- | --- |
| 网络 | 客户端配置、超时、错误转换 | API 路由和业务错误 |
| 实时通信 | 连接状态、重连、协议编码 | 会话权限、消息入库和回执规则 |
| 存储 | 缓存约定、迁移方法 | 业务表、查询、索引与保留策略 |
| 媒体 | 选择、录音、上传的接口约定 | 限制、OSS 配置、访问权限 |
| 通知 | 通道接口、平台适配 | 校园公告、受众、未读和发布权限 |
| UI | 主题、基础组件、状态约定 | 页面、文案、导航和产品交互 |
| 测试 | 测试样例、Fake 和工具 | 业务用例及验收证据 |

User、Post、Message 这样的名称也可能包含产品业务规则，不能仅凭名称通用就全部放入 Knot。客户端和服务端可以共享传输契约、枚举及协议版本；数据库实体、密码信息和服务器内部权限逻辑不得进入公共客户端契约。

## 客户端参考结构

```text
Compose 页面 → ViewModel / State Holder → Repository
                                          ├── HTTP / WebSocket
                                          └── SQLite
平台接口 → Android / iOS / Desktop 实现
```

采用单向数据流：UI 接收状态，事件调用状态持有者；Repository 统一管理数据来源。仅当业务步骤复杂或需要复用时增加 Use Case，避免每个简单查询都增加一层空包装。

长连接由登录会话级组件管理，页面订阅数据，不各自创建连接。退出登录时关闭连接、取消协程、清理订阅及用户缓存。上传与录音生命周期显式管理。

## 服务端参考结构

```text
HTTP / WebSocket 路由 → 业务服务 → 数据访问 / 外部服务适配器
```

初期采用模块化单体。网络请求、数据库事务和外部服务调用有明确边界；阻塞式数据库驱动不得阻塞请求事件线程。发送消息先鉴权和持久化，再发送事件；推送失败不能回滚已经保存的业务消息。

## 平台支持承诺

Android 是首要验收平台。iOS、macOS Desktop 先验证共享页面、网络和本地数据库，再逐项实现媒体和通知适配。共享 UI 不等于所有平台能力自动可用，README 只声明已验证的平台和功能。

## 暂不做

- 通用业务 DSL、编译器插件、代码生成平台。
- 微服务和复杂分布式部署。
- 自研操作系统级推送通道。
- 为凑模块数量提取未验证的基础库。
